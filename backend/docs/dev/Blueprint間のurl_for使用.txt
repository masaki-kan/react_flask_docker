================================================================================
  Blueprint 間での url_for() 使用
  - 他のファイルから別のBlueprintにアクセスする -
================================================================================

質問:
  app.py で Blueprint を登録していると、他のファイルでも
  その profile 識別名を使えるということ？
  例えば auth.py でアクセス使用できるとか


回答:
  はい、その通りです！完全に正しい理解です。

  app.register_blueprint() で登録すると、
  アプリケーション全体でそのBlueprintのエンドポイントが使えます。

  つまり:
    ✓ auth.py から profile の関数にアクセスできる
    ✓ items.py から users の関数にアクセスできる
    ✓ どのBlueprintファイルからでも、他のBlueprintを参照できる


================================================================================
1. Blueprint登録の効果
================================================================================

【app.py での登録】

# app.py
from flask import Flask
from api.auth import auth_bp
from api.profile import profile_bp
from api.users import users_bp
from api.items import items_bp

app = Flask(__name__)

# 全てのBlueprintを登録
app.register_blueprint(auth_bp)
app.register_blueprint(profile_bp)
app.register_blueprint(users_bp)
app.register_blueprint(items_bp)


【登録の効果】

登録すると、Flaskアプリケーション全体で以下が可能になります:

1. そのBlueprintのエンドポイントにアクセスできる
   └─ クライアントから /api/login などにアクセス可能

2. 他のBlueprintから url_for() で参照できる
   └─ auth.py から url_for('profile.xxx') が使える

3. アプリケーション全体でエンドポイントが共有される
   └─ どのファイルからでも、登録済みの全Blueprintを参照可能


【イメージ図】

┌────────────────────────────────────────────────────────────┐
│ Flask アプリケーション（app.py）                            │
├────────────────────────────────────────────────────────────┤
│                                                            │
│  app.register_blueprint(auth_bp)     ← 登録               │
│  app.register_blueprint(profile_bp)  ← 登録               │
│  app.register_blueprint(users_bp)    ← 登録               │
│  app.register_blueprint(items_bp)    ← 登録               │
│                                                            │
│  ┌──────────────────────────────────────────────────┐    │
│  │ 共有されたエンドポイント                         │    │
│  ├──────────────────────────────────────────────────┤    │
│  │ auth.login          → /api/login                 │    │
│  │ auth.register       → /api/register              │    │
│  │ profile.get_profile → /api/user/profile          │    │
│  │ users.getUsers      → /api/getUsers              │    │
│  │ items.getUserItems  → /api/getUserItems          │    │
│  └──────────────────────────────────────────────────┘    │
│       ↑                                                    │
│       これらのエンドポイントは                             │
│       アプリケーション全体で利用可能                       │
└────────────────────────────────────────────────────────────┘
              ↓
    どのファイルからでもアクセス可能
    ┌─────┬─────┬─────┬─────┐
    │auth │profile│users│items│
    │.py  │.py    │.py  │.py  │
    └─────┴─────┴─────┴─────┘


================================================================================
2. 実際の例: auth.py から profile にアクセス
================================================================================

【シナリオ】

ユーザーがログインに成功したら、プロフィールページのURLを返したい。


【実装】

# api/auth.py
from flask import Blueprint, jsonify, request, url_for
#                                            └──┬──┘
#                                         url_for をインポート

auth_bp = Blueprint('auth', __name__, url_prefix='/api')

@auth_bp.route('/login', methods=['POST'])
def login():
    email = request.json.get('email')
    password = request.json.get('password')

    # ログイン処理（省略）
    if authenticate(email, password):
        # プロフィールページのURLを生成
        profile_url = url_for('profile.get_authenticated_user_profile')
        #                     └────────────┬───────────────────────────┘
        #                     profile Blueprint の関数を参照

        return jsonify({
            'success': True,
            'message': 'ログイン成功',
            'redirect_url': profile_url  # /api/user/profile
        })
    else:
        return jsonify({
            'success': False,
            'message': 'ログイン失敗'
        }), 401


【なぜこれが動作するのか？】

1. app.py で profile_bp が登録されている
   └─ app.register_blueprint(profile_bp)

2. 登録により、'profile.get_authenticated_user_profile' という
   エンドポイントがアプリケーション全体で認識される

3. auth.py は同じFlaskアプリケーション内にあるため、
   url_for('profile.xxx') が使える


【重要なポイント】

✓ profile.py をインポートする必要はない
  └─ from api.profile import profile_bp は不要

✓ app.register_blueprint() されていれば使える
  └─ app.py で登録済みなら、どこからでもアクセス可能

✓ url_for() だけで参照できる
  └─ Flask が内部でエンドポイントを管理している

【例1: items.py から users にアクセス】

# api/items.py
from flask import Blueprint, jsonify, url_for

items_bp = Blueprint('items', __name__, url_prefix='/api')

@items_bp.route('/items/<int:item_id>', methods=['GET'])
def get_item_detail(item_id):
    # 商品情報を取得
    with get_db_connection() as conn:
        cursor = conn.cursor(dictionary=True)
        cursor.execute("""
            SELECT items.*, users.name as seller_name
            FROM items
            JOIN users ON items.user_id = users.user_id
            WHERE items.item_id = %s
        """, (item_id,))
        item = cursor.fetchone()
        cursor.close()

    # 出品者のプロフィールURLを追加
    seller_profile_url = url_for('profile.get_authenticated_user_profile')
    #                            └────────────┬───────────────────────────┘
    #                            profile Blueprint を参照

    # ユーザー一覧URLも追加
    users_list_url = url_for('users.getUsers')
    #                        └──────┬───────┘
    #                        users Blueprint を参照

    return jsonify({
        'item': item,
        'seller_profile_url': seller_profile_url,
        'users_list_url': users_list_url
    })

================================================================================
4. なぜ他のBlueprintを参照できるのか？
================================================================================

【Flask内部の仕組み】

┌─────────────────────────────────────────────────────────────┐
│ Step 1: Blueprint定義（各ファイル）                          │
└─────────────────────────────────────────────────────────────┘

# api/auth.py
auth_bp = Blueprint('auth', __name__, ...)

# api/profile.py
profile_bp = Blueprint('profile', __name__, ...)

# api/users.py
users_bp = Blueprint('users', __name__, ...)


この時点では:
  • 各Blueprintは独立している
  • 他のBlueprintを参照できない


┌─────────────────────────────────────────────────────────────┐
│ Step 2: Blueprint登録（app.py）                              │
└─────────────────────────────────────────────────────────────┘

# app.py
app.register_blueprint(auth_bp)
app.register_blueprint(profile_bp)
app.register_blueprint(users_bp)


登録時に Flask が行うこと:
  1. 各Blueprintのエンドポイントを取得
  2. アプリケーションのルーティングテーブルに追加
  3. エンドポイント名（'profile.get_profile'）を登録


┌─────────────────────────────────────────────────────────────┐
│ Step 3: ルーティングテーブル作成                             │
└─────────────────────────────────────────────────────────────┘

app.url_map に全てのエンドポイントが登録される:

┌──────────────────────────────┬─────────────────────┐
│ Endpoint                     │ URL                 │
├──────────────────────────────┼─────────────────────┤
│ auth.login                   │ /api/login          │
│ auth.register                │ /api/register       │
│ profile.get_profile          │ /api/user/profile   │
│ users.getUsers               │ /api/getUsers       │
│ items.getUserItems           │ /api/getUserItems   │
│ ...                          │ ...                 │
└──────────────────────────────┴─────────────────────┘


┌─────────────────────────────────────────────────────────────┐
│ Step 4: url_for() 使用（auth.py など）                       │
└─────────────────────────────────────────────────────────────┘

# api/auth.py
url = url_for('profile.get_profile')
      ↓
Flask は app.url_map を検索
      ↓
'profile.get_profile' が見つかる
      ↓
対応するURL '/api/user/profile' を返す


【重要なポイント】

✓ app.register_blueprint() で全エンドポイントが共有される
✓ Flask の app.url_map がエンドポイントを管理
✓ url_for() は app.url_map を参照してURLを生成
✓ どのファイルからでも、登録済みのエンドポイントにアクセス可能

5. インポート不要の理由
================================================================================

【質問: なぜ profile.py をインポートしなくても使えるのか？】

回答: Flask がエンドポイントを文字列で管理しているため


【詳細説明】

❌ 必要ない
────────────────────────────────────────
# api/auth.py
from api.profile import profile_bp  # ← インポート不要

url = url_for('profile.get_authenticated_user_profile')


✅ これだけでOK
────────────────────────────────────────
# api/auth.py
from flask import url_for

url = url_for('profile.get_authenticated_user_profile')
#             └────────────┬───────────────────────────┘
#             文字列として指定


【理由】

1. app.py で既に profile_bp が登録されている
   └─ app.register_blueprint(profile_bp)

2. 登録時に Flask がエンドポイントを記録
   └─ 'profile.get_authenticated_user_profile' という文字列

3. url_for() は文字列でエンドポイントを検索
   └─ オブジェクトのインポートは不要

4. Flask の app.url_map がエンドポイントを管理
   └─ どこからでもアクセス可能


【例外: オブジェクトとして参照する場合】

もし profile_bp オブジェクト自体にアクセスしたい場合は
インポートが必要:

# api/auth.py
from api.profile import profile_bp

# profile_bp の設定を参照
print(profile_bp.url_prefix)  # /api


ただし、url_for() を使うだけなら不要！

【特定のエンドポイントを検索】

# app.py
def find_endpoint(keyword):
    """キーワードでエンドポイントを検索"""
    results = []
    for rule in app.url_map.iter_rules():
        if keyword.lower() in rule.endpoint.lower():
            results.append(f"{rule.endpoint} → {rule.rule}")
    return results

# 使用例
print(find_endpoint('profile'))
# 出力:
# profile.get_authenticated_user_profile → /api/user/profile
# profile.update_profile → /api/user/profile

7. よくある質問
================================================================================

Q1. auth.py から profile.py のエンドポイントを使える？
────────────────────────────────────────

A. はい、使えます。

# api/auth.py
from flask import url_for

url = url_for('profile.get_authenticated_user_profile')
# → /api/user/profile

条件: app.py で両方のBlueprintが登録されていること


Q2. profile.py をインポートする必要はある？
────────────────────────────────────────

A. いいえ、不要です。

url_for() は文字列でエンドポイントを指定するため、
オブジェクトのインポートは必要ありません。


Q3. 登録されていないBlueprintを参照できる？
────────────────────────────────────────

A. いいえ、できません。

# app.py で登録していない場合
# app.register_blueprint(profile_bp)  # ← コメントアウト

# api/auth.py
url = url_for('profile.get_profile')
# → BuildError: Could not build url for endpoint 'profile.get_profile'


Q4. 循環参照は問題にならない？
────────────────────────────────────────

A. 問題ありません。

# api/auth.py
url = url_for('profile.get_profile')  # profile を参照

# api/profile.py
url = url_for('auth.login')  # auth を参照

これは問題ない。url_for() は文字列参照なので。


Q5. 同じエンドポイント名が重複したら？
────────────────────────────────────────

A. エラーになります。

# api/auth.py
@auth_bp.route('/test')
def get_data():  # endpoint: 'auth.get_data'
    pass

# api/users.py
@users_bp.route('/test')
def get_data():  # endpoint: 'users.get_data' (別のBlueprint)
    pass

これは問題ない（Blueprintが違うので）。

ただし、同じBlueprint内で重複は不可:

# api/auth.py
@auth_bp.route('/test1')
def get_data():
    pass

@auth_bp.route('/test2')
def get_data():  # ← エラー！同じ関数名
    pass


Q6. url_for() はどこで使える？
────────────────────────────────────────

A. Flaskアプリケーション内ならどこでも使えます。

使える場所:
  ✓ Blueprint内の関数
  ✓ app.py
  ✓ ユーティリティ関数
  ✓ テンプレート（Jinja2）

使えない場所:
  ✗ アプリケーションコンテキスト外
    （app.app_context() が必要）

【例: ログイン成功後の複数リンク返却】

# api/auth.py
from flask import Blueprint, jsonify, request, url_for

auth_bp = Blueprint('auth', __name__, url_prefix='/api')

@auth_bp.route('/login', methods=['POST'])
def login():
    email = request.json.get('email')
    password = request.json.get('password')

    # ログイン処理
    if authenticate(email, password):
        # 複数のBlueprintからリンクを生成
        return jsonify({
            'success': True,
            'message': 'ログイン成功',
            'links': {
                'profile': url_for('profile.get_authenticated_user_profile'),
                #                  └─────────┬──────────────────────────┘
                #                  profile Blueprint

                'items': url_for('items.getUserItems'),
                #                └────┬─────┘
                #                items Blueprint

                'users': url_for('users.getUsers'),
                #                └────┬────┘
                #                users Blueprint

                'my_items': url_for('items.getMyItems'),
                #                   └────┬─────┘
                #                   items Blueprint

                'saved_items': url_for('saves.getSaves'),
                #                      └────┬────┘
                #                      saves Blueprint

                'logout': url_for('auth.logout')
                #                 └───┬───┘
                #                 自分自身のBlueprint
            }
        })
    else:
        return jsonify({
            'success': False,
            'message': 'ログイン失敗'
        }), 401

# api/auth.py

@auth_bp.route('/login', methods=['POST'])
def login():
    # profile Blueprint のエンドポイントを参照
    profile_url = url_for('profile.get_authenticated_user_profile')

    # users Blueprint のエンドポイントを参照
    users_url = url_for('users.getUsers')

    # items Blueprint のエンドポイントを参照

【条件】

app.py で全てのBlueprintが登録されていること:
