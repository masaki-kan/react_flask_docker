1. 概要
================================================================================

このアプリケーションは、MySQL データベースへの接続に「接続プール」という仕組みを
採用しています。接続プールを使うことで、以下のメリットがあります：

  ✓ 高速なDB接続（毎回接続を作り直さない）
  ✓ リソースの効率的な管理
  ✓ 同時接続数の制御
  ✓ 自動的な接続の再利用

接続プールサイズ: 10接続
接続タイムアウト: 30秒

4. DB接続プールの仕組み
================================================================================

【接続プールとは？】

  通常のDB接続:
    リクエスト毎に接続 → クエリ実行 → 切断
    ↑ 毎回接続を作るのは遅い！

  接続プール:
    アプリ起動時に10個の接続を作成
    ↓
    リクエストが来たら空いている接続を貸し出す
    ↓
    使い終わったら接続をプールに返却
    ↓
    次のリクエストで再利用
    ↑ 高速！効率的！


【接続プールの設定 (db_utils.py 11-22行目)】

  db_pool = pooling.MySQLConnectionPool(
      pool_name="mypool",            # プール名
      pool_size=10,                  # 同時に使える接続数
      pool_reset_session=True,       # 接続を返却時にリセット
      host=os.getenv("DB_HOST"),     # DBホスト
      user=os.getenv("DB_USER"),     # DBユーザー
      password=os.getenv("DB_PASSWORD"),
      database=os.getenv("DB_NAME"),
      autocommit=False,              # 手動コミット
      connection_timeout=30,         # タイムアウト30秒
      buffered=True                  # 結果をバッファリング
  )


【接続の流れ】

  1. アプリ起動時
     ┌──────────────────────────────┐
     │ 接続プール (10接続)           │
     │ [conn1][conn2]...[conn10]    │
     └──────────────────────────────┘

  2. リクエスト1が来た
     ┌──────────────────────────────┐
     │ [使用中][conn2]...[conn10]   │ → リクエスト1に貸出
     └──────────────────────────────┘

  3. リクエスト2が来た
     ┌──────────────────────────────┐
     │ [使用中][使用中]...[conn10]  │ → リクエスト2に貸出
     └──────────────────────────────┘

  4. リクエスト1が終了
     ┌──────────────────────────────┐
     │ [返却][使用中]...[conn10]    │ → conn1が再利用可能に
     └──────────────────────────────┘

【パターン1: 推奨される使い方 (with文)】
────────────────────────────────────────

from utils.db_utils import get_db_connection

def get_user_by_id(user_id):
    """ユーザー情報を取得"""
    with get_db_connection() as conn:
        cursor = conn.cursor(dictionary=True)
        try:
            cursor.execute("""
                SELECT user_id, name, email
                FROM users
                WHERE user_id = %s
            """, (user_id,))
            user = cursor.fetchone()
            return user
        finally:
            cursor.close()
    # ← with文を抜けると自動的にconnがプールに返却される


【パターン2: データ更新・挿入の場合】
────────────────────────────────────────

from utils.db_utils import get_db_connection

def create_user(name, email, password):
    """新規ユーザー作成"""
    with get_db_connection() as conn:
        cursor = conn.cursor()
        try:
            cursor.execute("""
                INSERT INTO users (name, email, password)
                VALUES (%s, %s, %s)
            """, (name, email, password))

            conn.commit()  # 重要: 変更を確定

            user_id = cursor.lastrowid  # 挿入されたIDを取得
            return user_id
        except Exception as e:
            conn.rollback()  # エラー時はロールバック
            raise e
        finally:
            cursor.close()


【パターン3: トランザクション処理】
────────────────────────────────────────

def create_trade(item_id, seller_id, buyer_id):
    """取引を作成し、商品ステータスを更新"""
    with get_db_connection() as conn:
        cursor = conn.cursor()
        try:
            # 1. 取引レコード作成
            cursor.execute("""
                INSERT INTO trades (item_id, seller_id, buyer_id)
                VALUES (%s, %s, %s)
            """, (item_id, seller_id, buyer_id))

            trade_id = cursor.lastrowid

            # 2. 商品ステータス更新
            cursor.execute("""
                UPDATE items
                SET status = 'trading'
                WHERE item_id = %s
            """, (item_id,))

            # 両方成功したらコミット
            conn.commit()
            return trade_id

        except Exception as e:
            # どちらかが失敗したらロールバック
            conn.rollback()
            raise e
        finally:
            cursor.close()


【パターン4: Blueprintでの使用例（実際のAPIコード）】

from flask import Blueprint, jsonify, request
from utils.db_utils import get_db_connection

admin_bp = Blueprint('admin', __name__, url_prefix='/api/dashboard')

@admin_bp.route('/users', methods=['GET'])
def get_users():
    """管理画面: ユーザー一覧取得"""
    try:
        with get_db_connection() as conn:
            cursor = conn.cursor(dictionary=True)
            cursor.execute("""
                SELECT user_id, name, email, created_at
                FROM users
                WHERE is_deleted = FALSE
                ORDER BY created_at DESC
            """)
            users = cursor.fetchall()
            cursor.close()

        return jsonify({
            'success': True,
            'data': users
        })
    except Exception as e:
        return jsonify({
            'success': False,
            'message': str(e)
        }), 500


【パターン5: 複数クエリの実行】

def get_trade_detail(trade_id):
    """取引詳細を取得（複数テーブルから）"""
    with get_db_connection() as conn:
        cursor = conn.cursor(dictionary=True)
        try:
            # 取引情報
            cursor.execute("""
                SELECT * FROM trades WHERE trade_id = %s
            """, (trade_id,))
            trade = cursor.fetchone()

            # チャットメッセージ
            cursor.execute("""
                SELECT * FROM trade_messages
                WHERE trade_id = %s
                ORDER BY sent_at ASC
            """, (trade_id,))
            messages = cursor.fetchall()

            # 発送情報
            cursor.execute("""
                SELECT * FROM shipping_info
                WHERE trade_id = %s
            """, (trade_id,))
            shipping = cursor.fetchall()

            return {
                'trade': trade,
                'messages': messages,
                'shipping': shipping
            }
        finally:
            cursor.close()

6. エラーハンドリング
================================================================================

【自動エラーハンドリング (get_db_connection)】

get_db_connection() は以下を自動で行います:

  ✓ エラー発生時に自動ロールバック
  ✓ finally で必ず接続を閉じる（プールに返却）
  ✓ エラーを再送出してログに記録


【実装コード (db_utils.py 28-41行目)】

@contextmanager
def get_db_connection():
    conn = None
    try:
        conn = db_pool.get_connection()  # プールから取得
        yield conn                        # 呼び出し元に渡す
    except Exception as e:
        if conn and conn.is_connected():
            conn.rollback()               # エラー時ロールバック
        raise e                           # エラーを再送出
    finally:
        if conn and conn.is_connected():
            conn.close()                  # プールに返却


【起動時のリトライ処理 (app.py 115-149行目)】

def initialize_app():
    max_retries = 30
    retry_count = 0

    while retry_count < max_retries:
        try:
            init_db_pool()  # 接続プール初期化
            # ... その他の初期化
            return
        except Exception as e:
            retry_count += 1
            if "Can't connect to MySQL server" in str(e):
                # 2秒待ってリトライ
                logging.warning(f"リトライ {retry_count}/{max_retries}...")
                time.sleep(2)
                continue
            else:
                raise

  → Docker起動時など、MySQLがまだ起動していない場合に有効


【よくあるエラーと対処法】

1. "Can't connect to MySQL server"
   原因: MySQLサーバーが起動していない / 接続情報が間違っている
   対処:
     - MySQLが起動しているか確認
     - .env.development の DB_HOST, DB_USER, DB_PASSWORD を確認

2. "Access denied for user"
   原因: ユーザー名またはパスワードが間違っている
   対処:
     - .env.development のDB_USER, DB_PASSWORDを確認

3. "Unknown database"
   原因: 指定したデータベースが存在しない
   対処:
     - MySQL で CREATE DATABASE [DB_NAME] を実行

4. "PoolError: Failed getting connection"
   原因: プールの接続が全て使用中
   対処:
     - pool_size を増やす（現在10）
     - 接続を正しくclose()しているか確認

【テーブル間のリレーション】

  users (ユーザー)
    ├─ 1:N → items (商品)
    ├─ 1:N → trades (取引) ※ seller/buyer として
    ├─ 1:N → profile_images
    ├─ M:N → follows (フォロー関係)
    └─ 1:N → likes (お気に入り)

  items (商品)
    ├─ 1:N → item_images (商品画像)
    ├─ 1:1 → trades (取引の対象商品)
    └─ M:N → likes

  trades (取引)
    ├─ 1:N → trade_messages (チャット)
    ├─ 1:N → shipping_info (発送情報)
    ├─ 1:N → trade_confirmations (受取確認)
    └─ N:1 → items (seller/buyer exchange item)

  archived_trades (完了取引)
    ├─ 1:N → archived_items (商品スナップショット)
    └─ 1:N → archived_item_images


【重要なカラム】

users テーブル:
  - user_id          : 主キー
  - email            : メールアドレス（ログイン用）
  - type             : 0=管理者, 1=一般ユーザー
  - is_deleted       : 論理削除フラグ
  - deleted_at       : 削除日時

items テーブル:
  - item_id          : 主キー
  - status           : 'available'/'trading'/'exchanged'/'deleted'
  - user_id          : 出品者

trades テーブル:
  - trade_id         : 主キー
  - item_id          : 対象商品

  - buyer_id         : 申請者
  - seller_exchange_item_id : Sellerが選んだ交換商品
  - buyer_exchange_item_id  : Buyerが選んだ交換商品

archived_trades テーブル:
  - archive_trade_id     : 主キー
  - original_trade_id    : 元のtrade_id
  - seller_name          : Sellerの名前（スナップショット）
  - buyer_name           : Buyerの名前（スナップショット）
  - trade_completed_at   : 完了日時

8. トラブルシューティング
================================================================================

【問題1: アプリが起動しない】

チェックポイント:
  □ MySQLが起動しているか？
    → docker ps または sudo systemctl status mysql

  □ .env.development が存在するか？
    → ls -la でファイル確認

  □ 環境変数が正しく設定されているか？
    → .env.development の内容を確認
    DB_HOST=localhost  (Dockerの場合は mysql)
    DB_USER=root
    DB_PASSWORD=your_password
    DB_NAME=your_database

  □ データベースが作成されているか？
    → mysql -u root -p
    → SHOW DATABASES;


【問題2: "PoolError: Failed getting connection"】

原因: 接続プールが枯渇している

解決策:
  1. db_utils.py の pool_size を増やす
     pool_size=10 → pool_size=20

  2. 長時間接続を保持していないか確認
     必ず with文を使い、処理が終わったら返却する

  3. デッドロックが発生していないか確認
     アプリを再起動して接続をリセット


【問題3: データが更新されない】

原因: commit() していない

解決策:
  INSERT/UPDATE/DELETE の後に必ず conn.commit() を実行

  例:
    cursor.execute("UPDATE users SET name = %s WHERE user_id = %s", (...))
    conn.commit()  # ← これがないと反映されない


【問題4: "Access denied for user 'root'@'localhost'"】

原因: パスワードまたはユーザー名が間違っている

解決策:
  1. MySQL にログインして確認
     mysql -u root -p

  2. ユーザーが存在するか確認
     SELECT user, host FROM mysql.user;

  3. 権限を付与
     GRANT ALL PRIVILEGES ON your_database.* TO 'root'@'localhost';
     FLUSH PRIVILEGES;


【問題5: テーブルが作成されない】

原因: initialize_database() でエラーが発生している

解決策:
  1. ログを確認
     ターミナルに "Database initialization error" が出ていないか

  2. 手動でテーブル作成を実行
     mysql -u root -p your_database < database.sql

  3. database.py の SQL文法を確認
     CREATE TABLE IF NOT EXISTS ... が正しいか


【問題6: Docker環境で接続できない】

原因: ホスト名が間違っている

解決策:
  .env.development を以下のように修正:
    ❌ DB_HOST=localhost
    ✅ DB_HOST=mysql  (docker-compose.ymlのサービス名)

まとめ
================================================================================

【DB接続の基本】
  1. アプリ起動時に接続プールを作成 (10接続)
  2. リクエスト時にプールから接続を借りる
  3. 処理が終わったら接続をプールに返す
  4. with文を使えば自動でrollback/closeしてくれる

【ベストプラクティス】
  ✓ 必ず with get_db_connection() を使う
  ✓ INSERT/UPDATE/DELETE の後は conn.commit()
  ✓ エラー時は conn.rollback()
  ✓ cursor.close() を忘れない
  ✓ 長時間接続を保持しない

【避けるべきパターン】
  ✗ 接続を手動で管理する（get_db_connection_legacy）
  ✗ commit() を忘れる
  ✗ close() を忘れる
  ✗ エラーハンドリングをしない

【参考ファイル】

  - utils/db_utils.py     : DB接続プール管理
  - database.py           : テーブル定義
  - api/admin.py          : 実際の使用例

【環境変数】
  .env.development / .env.production に以下を設定:
    DB_HOST=localhost
    DB_USER=root
    DB_PASSWORD=your_password
    DB_NAME=your_database
