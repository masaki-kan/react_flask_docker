================================================================================
  Blueprint の name パラメータ解説
  - Blueprint('profile', ...) の 'profile' とは何か？ -
================================================================================

質問:
  Blueprint('profile', __name__, url_prefix='/api')
                ↑
            この 'profile' は何のための名前？


回答:
  'profile' は Blueprint の識別名（内部名）で、URLには影響しません。
  主に url_for() や endpoint の指定に使われます。


================================================================================
1. Blueprint の name パラメータの役割
================================================================================

【構文】

Blueprint(name, import_name, url_prefix)
          ↓
Blueprint('profile', __name__, url_prefix='/api')
          └──┬───┘
         Blueprint名


【役割】

'profile' という名前は、以下の用途で使われます：

1. url_for() での参照
2. endpoint の名前空間
3. エラーメッセージでの識別
4. デバッグ時の識別

重要: URLには直接影響しません！


================================================================================
2. URLには影響しない
================================================================================

【例】

# api/profile.py
profile_bp = Blueprint('profile', __name__, url_prefix='/api')
                       └──┬───┘                      └───┬──┘
                    Blueprint名（内部）           URLに影響する

@profile_bp.route('/getProfile', methods=['POST'])
                  └─────┬──────┘
                    URLに影響する


【実際のURL】

url_prefix='/api' + @route('/getProfile')
    ↓
最終的なURL: /api/getProfile

Blueprint名 'profile' はURLに含まれない！


【別の名前にしても同じURL】

パターンA:
  profile_bp = Blueprint('profile', __name__, url_prefix='/api')
  @profile_bp.route('/getProfile')
  → URL: /api/getProfile

パターンB:
  profile_bp = Blueprint('user_profile', __name__, url_prefix='/api')
  @profile_bp.route('/getProfile')
  → URL: /api/getProfile (同じ！)

パターンC:
  profile_bp = Blueprint('xyz', __name__, url_prefix='/api')
  @profile_bp.route('/getProfile')
  → URL: /api/getProfile (同じ！)


結論: Blueprint名を変えてもURLは変わらない


================================================================================
3. Blueprint名の主な用途
================================================================================

【用途1: url_for() での参照】
────────────────────────────────────────

# api/profile.py
profile_bp = Blueprint('profile', __name__, url_prefix='/api')

@profile_bp.route('/getProfile', methods=['POST'])
def get_profile():
    return jsonify({'message': 'プロフィール取得'})


# 別のファイルから参照する場合
from flask import url_for

# Blueprint名 + 関数名 で参照
url = url_for('profile.get_profile')
#             └──┬──┘ └────┬────┘
#          Blueprint名   関数名

print(url)  # → /api/getProfile


【具体例】

# api/auth.py
auth_bp = Blueprint('auth', __name__, url_prefix='/api')

@auth_bp.route('/login', methods=['POST'])
def login():
    # ログイン成功後、プロフィールページのURLを返す
    from flask import url_for
    profile_url = url_for('profile.get_profile')
    #                     └──┬──┘
    #                  Blueprint名 'profile'
    return jsonify({
        'message': 'ログイン成功',
        'redirect_url': profile_url  # /api/getProfile
    })


【用途2: endpoint の名前空間】
────────────────────────────────────────

endpoint とは、ルートを一意に識別する名前。

# api/profile.py
profile_bp = Blueprint('profile', __name__, url_prefix='/api')

@profile_bp.route('/getProfile')
def get_profile():
    pass

# このルートの endpoint は 'profile.get_profile'
#                          └──┬──┘ └────┬────┘
#                       Blueprint名   関数名


# app.py でエンドポイント一覧を確認
for rule in app.url_map.iter_rules():
    print(f"Endpoint: {rule.endpoint}, URL: {rule.rule}")

# 出力:
# Endpoint: profile.get_profile, URL: /api/getProfile
# Endpoint: auth.login, URL: /api/login
# Endpoint: users.get_users, URL: /api/getUsers


【用途3: エラーメッセージでの識別】
────────────────────────────────────────

エラーが発生した時、どの Blueprint で起きたか分かる。

# エラーメッセージ例
werkzeug.routing.BuildError: Could not build url for endpoint 'profile.get_profile'
                                                                └──┬──┘
                                                             Blueprint名


【用途4: デバッグ時の識別】
────────────────────────────────────────

# app.py
print(f"登録された Blueprint: {app.blueprints.keys()}")
# 出力: dict_keys(['auth', 'profile', 'users', 'items', ...])


================================================================================
4. 実際の例で比較
================================================================================

【例1: Blueprint名を変えてもURLは同じ】

パターンA:
──────────────────────────────────────────────
# api/profile.py
profile_bp = Blueprint('profile', __name__, url_prefix='/api')
#                      └──┬───┘
#                   Blueprint名: 'profile'

@profile_bp.route('/getProfile', methods=['POST'])
def get_profile():
    return jsonify({'name': '太郎'})

# クライアントからアクセス
fetch('/api/getProfile')  # ✓ 動作する

# url_for()
url_for('profile.get_profile')  # → /api/getProfile


パターンB: Blueprint名を変更
──────────────────────────────────────────────
# api/profile.py
profile_bp = Blueprint('user_profile_handler', __name__, url_prefix='/api')
#                      └────────┬────────┘
#                   Blueprint名: 'user_profile_handler'

@profile_bp.route('/getProfile', methods=['POST'])
def get_profile():
    return jsonify({'name': '太郎'})

# クライアントからアクセス
fetch('/api/getProfile')  # ✓ 動作する（URLは同じ！）

# url_for()
url_for('user_profile_handler.get_profile')  # → /api/getProfile
#       └─────────┬─────────┘
#          Blueprint名が変わった


結論:
  • クライアントのURL: /api/getProfile (変わらない)
  • url_for()の引数: 'user_profile_handler.get_profile' (変わる)


【例2: 複数のBlueprint名が同じだとエラー】

# api/profile.py
profile_bp = Blueprint('user', __name__, url_prefix='/api')
#                      └─┬─┘
#                   Blueprint名: 'user'


# api/users.py
users_bp = Blueprint('user', __name__, url_prefix='/api')
#                    └─┬─┘
#                Blueprint名: 'user' (重複！)


# app.py
app.register_blueprint(profile_bp)
app.register_blueprint(users_bp)  # ← エラー！

# AssertionError: A blueprint's name collision occurred between
# <flask.blueprints.Blueprint 'user'> and <flask.blueprints.Blueprint 'user'>


解決策: 一意な名前にする
──────────────────────────────────────────────
profile_bp = Blueprint('profile', __name__, url_prefix='/api')
users_bp = Blueprint('users', __name__, url_prefix='/api')


【例3: 変数名とBlueprint名は別物】

# api/profile.py
my_blueprint = Blueprint('profile', __name__, url_prefix='/api')
#  └────┬────┘          └──┬───┘
#   変数名             Blueprint名

@my_blueprint.route('/getProfile')
def get_profile():
    pass

# url_for()
url_for('profile.get_profile')  # ✓ 正しい（Blueprint名を使う）
url_for('my_blueprint.get_profile')  # ✗ エラー（変数名は使えない）


# app.py
from api.profile import my_blueprint  # 変数名でインポート

app.register_blueprint(my_blueprint)  # 変数名で登録

# 登録後の確認
print(app.blueprints.keys())
# 出力: dict_keys(['profile', ...])  ← Blueprint名が表示される
#                   └──┬───┘
#                Blueprint名 'profile'


================================================================================
5. よくある質問
================================================================================

Q1. Blueprint名と変数名は合わせるべき？
────────────────────────────────────────

A. 推奨: 合わせる方が分かりやすい

✅ 良い例
  profile_bp = Blueprint('profile', __name__, url_prefix='/api')
  #  └──┬──┘            └──┬───┘
  # 変数名            Blueprint名
  # 両方 'profile' で統一（_bpは接尾辞）


❌ 悪い例
  xyz = Blueprint('profile', __name__, url_prefix='/api')
  # 変数名とBlueprint名が違って混乱する


Q2. Blueprint名は何でも良い？
────────────────────────────────────────

A. 技術的には何でも良いが、以下を推奨:

✅ 推奨
  • 小文字
  • 単数形
  • 機能を表す名前

  例: 'auth', 'profile', 'user', 'item', 'trade'


❌ 非推奨
  • 大文字: 'Profile'
  • 複数形: 'users' (変数名とかぶる)
  • 意味不明: 'bp1', 'handler', 'x'


Q3. Blueprint名を後から変更できる？
────────────────────────────────────────

A. 可能だが、影響がある

変更すると:
  • url_for() の引数を全て変更する必要がある
  • エラーメッセージが変わる

例:
  変更前: url_for('profile.get_profile')
  変更後: url_for('user_profile.get_profile')

  → すべての url_for() を修正する必要がある


Q4. url_prefixだけ変えたらURLは変わる？
────────────────────────────────────────

A. はい、url_prefixはURLに直接影響する

パターンA:
  profile_bp = Blueprint('profile', __name__, url_prefix='/api')
  @profile_bp.route('/getProfile')
  → URL: /api/getProfile

パターンB:
  profile_bp = Blueprint('profile', __name__, url_prefix='/api/v1')
  @profile_bp.route('/getProfile')
  → URL: /api/v1/getProfile (変わる！)

パターンC:
  profile_bp = Blueprint('profile', __name__, url_prefix='/user')
  @profile_bp.route('/getProfile')
  → URL: /user/getProfile (変わる！)


Q5. Blueprint名にハイフンやスラッシュは使える？
────────────────────────────────────────

A. 技術的には可能だが、推奨しない

❌ 非推奨
  Blueprint('user-profile', ...)  # ハイフン
  Blueprint('user/profile', ...)  # スラッシュ

✅ 推奨
  Blueprint('user_profile', ...)  # アンダースコア


理由:
  url_for('user-profile.get_profile')  # Pythonの識別子として使いにくい
  url_for('user_profile.get_profile')  # こちらが自然

7. まとめ
================================================================================

【Blueprint名の役割】

Blueprint('profile', __name__, url_prefix='/api')
          └──┬───┘                      └───┬──┘
       内部識別名                    URLに影響
      (url_for()で使う)


【重要ポイント】

✓ Blueprint名はURLに影響しない
  → URLは url_prefix + @route() で決まる

✓ Blueprint名は url_for() で使う
  → url_for('profile.get_profile')

✓ Blueprint名は一意である必要がある
  → 同じ名前を複数定義するとエラー

✓ Blueprint名と変数名を合わせると分かりやすい
  → profile_bp = Blueprint('profile', ...)


【URL構造の復習】

完全なURL = url_prefix + @blueprint.route()

例:
  profile_bp = Blueprint('profile', __name__, url_prefix='/api')
  @profile_bp.route('/getProfile')

  → URL: /api + /getProfile = /api/getProfile

  'profile' はURLに含まれない！


【実践例】

# api/profile.py
profile_bp = Blueprint('profile', __name__, url_prefix='/api')
#  変数名: profile_bp
#  Blueprint名: 'profile'
#  url_prefix: '/api'

@profile_bp.route('/getProfile', methods=['POST'])
def get_profile():
    return jsonify({'name': '太郎'})

# 使い方
# 1. クライアントからアクセス
fetch('/api/getProfile')  # URL

# 2. url_for()
url_for('profile.get_profile')  # Blueprint名.関数名

# 3. endpoint
# 'profile.get_profile'
