================================================================================
Stripe環境設定ガイド
作成日: 2025-12-04
================================================================================

このドキュメントでは、Stripe決済の開発環境と本番環境の設定方法を説明します。

================================================================================
1. 環境変数の設定
================================================================================

### 開発環境（テストモード）

.env.development ファイルに以下を追加:

```
# Stripe設定（テストモード）
STRIPE_MODE=test
STRIPE_SECRET_KEY=sk_test_xxxxxxxxxxxxxxxxxxxxxx
STRIPE_PUBLISHABLE_KEY=pk_test_xxxxxxxxxxxxxxxxxxxxxx
PLATFORM_URL=http://localhost:5173
```

### 本番環境

.env.production ファイルに以下を追加:

```
# Stripe設定（本番モード）
STRIPE_MODE=live
STRIPE_SECRET_KEY=sk_live_xxxxxxxxxxxxxxxxxxxxxx
STRIPE_PUBLISHABLE_KEY=pk_live_xxxxxxxxxxxxxxxxxxxxxx
PLATFORM_URL=https://yourdomain.com
```

================================================================================
2. Stripeキーの取得方法
================================================================================

### テストモード用キーの取得

1. Stripeダッシュボードにログイン: https://dashboard.stripe.com
2. 左上のトグルが「テストモード」になっていることを確認
3. 「開発者」→「APIキー」をクリック
4. 「公開可能キー」と「シークレットキー」をコピー

### 本番モード用キーの取得

1. Stripeダッシュボードにログイン
2. 左上のトグルを「本番モード」に切り替え
3. 「開発者」→「APIキー」をクリック
4. 「公開可能キー」と「シークレットキー」をコピー

重要: 本番モードに切り替える前に、Stripeアカウントの本人確認を完了してください。

================================================================================

4. データベースマイグレーション
================================================================================

### マイグレーションSQLの実行

以下のSQLをTablePlusなどで実行してください:

```sql
-- usersテーブルにStripe Connected Account関連のカラムを追加
ALTER TABLE users
ADD COLUMN IF NOT EXISTS stripe_account_id VARCHAR(255) DEFAULT NULL
  COMMENT 'Stripe Connected Account ID',
ADD COLUMN IF NOT EXISTS stripe_onboarding_completed BOOLEAN DEFAULT FALSE
  COMMENT 'Stripeオンボーディング完了フラグ',
ADD COLUMN IF NOT EXISTS stripe_charges_enabled BOOLEAN DEFAULT FALSE
  COMMENT 'Stripe決済受付可能フラグ',
ADD COLUMN IF NOT EXISTS stripe_payouts_enabled BOOLEAN DEFAULT FALSE
  COMMENT 'Stripe出金可能フラグ',
ADD COLUMN IF NOT EXISTS stripe_details_submitted BOOLEAN DEFAULT FALSE
  COMMENT 'Stripe詳細情報提出済みフラグ';

-- tradesテーブルにStripe Transfer ID追加
ALTER TABLE trades
ADD COLUMN IF NOT EXISTS stripe_transfer_id VARCHAR(255) DEFAULT NULL
  COMMENT 'Stripe Transfer ID（販売者への送金）';

-- archived_tradesテーブルにも追加
ALTER TABLE archived_trades
ADD COLUMN IF NOT EXISTS stripe_transfer_id VARCHAR(255) DEFAULT NULL
  COMMENT 'Stripe Transfer ID（販売者への送金）';
```

マイグレーションファイル: `backend/migrations/008_add_stripe_connect_columns.sql`

================================================================================
5. 開発環境での動作
================================================================================

### STRIPE_MODE=test の場合

決済フロー:
✅ PaymentIntentはダミーIDを生成（実際の決済なし）
✅ TransferはダミーIDを生成（実際の送金なし）
✅ 販売者登録は自動完了（オンボーディング不要）
✅ 銀行口座情報は不要
✅ 本人確認書類は不要

販売者登録:
- 「販売者として登録する」ボタンをクリック
- 即座にダミーのstripe_account_idが作成される
- オンボーディング画面への遷移なし

決済テスト:
- テストカード番号: 4242 4242 4242 4242
- 有効期限: 任意の未来の日付
- CVC: 任意の3桁
- 実際のお金は動かない

================================================================================
6. 本番環境での動作
================================================================================

### STRIPE_MODE=live の場合

決済フロー:
✅ 実際のStripe PaymentIntentを作成
✅ 実際の決済が実行される
✅ 実際のTransferで販売者に送金
✅ 販売者の銀行口座に実際に入金される

販売者登録:
1. 「販売者として登録する」ボタンをクリック
2. Stripeのオンボーディング画面に遷移
3. 以下を入力:
   - 氏名、住所、生年月日
   - 銀行口座情報（銀行名、支店、口座番号）
   - 電話番号
4. 登録完了後、プロフィール画面に戻る
5. 本人確認書類は取引量に応じて後で要求される

決済:
- 実際のクレジットカードで決済
- 実際のお金が動く
- 購入者のカードから引き落とし
- 販売者の銀行口座に入金

7. 環境の切り替え方法
================================================================================

### 開発環境 → 本番環境

1. .env.productionファイルを作成
2. STRIPE_MODE=liveに設定
3. 本番用のStripeキーを設定
4. Stripeアカウントの本人確認を完了
5. アプリを本番モードで起動

```bash
# バックエンド
export FLASK_ENV=production
python app.py

# フロントエンド
npm run build
```

### 本番環境 → 開発環境

1. STRIPE_MODE=testに変更
2. テスト用のStripeキーに戻す
3. アプリを再起動

8. トラブルシューティング
================================================================================

### Q1: 販売者登録ボタンを押してもエラーになる

A: 以下を確認:
- STRIPE_SECRET_KEYが正しく設定されているか
- データベースマイグレーションが完了しているか
- バックエンドのログを確認

### Q2: オンボーディング画面が表示されない

A: 以下を確認:
- STRIPE_MODE=liveになっているか
- PLATFORM_URLが正しいか
- Stripeのアカウント状態を確認

### Q3: 決済は成功するが送金されない

A: 以下を確認:
- 販売者のstripe_account_idが設定されているか
- stripe_payouts_enabledがtrueか
- complete_purchase_trade APIが正しく呼ばれているか

### Q4: 開発環境で実際の決済が実行される

A: 以下を確認:
- STRIPE_MODE=testになっているか
- 環境変数が正しく読み込まれているか
- アプリを再起動

9. セキュリティ注意事項
================================================================================

重要事項:

1. **シークレットキーは公開しない**
   - Gitにコミットしない
   - .envファイルを.gitignoreに追加
   - 環境変数で管理する

2. **本番キーとテストキーを混同しない**
   - sk_live_ で始まるキーは本番用
   - sk_test_ で始まるキーはテスト用

3. **PLATFORM_URLは正しく設定**
   - オンボーディングの戻り先URLとして使用
   - HTTPSを推奨（本番環境）

4. **定期的にキーをローテーション**
   - 漏洩の疑いがある場合は即座に無効化
   - Stripeダッシュボードで新しいキーを生成

- 銀行口座登録不要

- 銀行口座登録必須

この設計により:
✅ 開発環境で安全にテスト可能
✅ 本番環境への移行が簡単
✅ コードの変更不要（環境変数のみ）
✅ セキュリティが確保される
