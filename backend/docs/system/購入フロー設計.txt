1. 概要
================================================================================

【目的】
  現在の「交換」フローに加えて、「購入」フローを追加する。

【背景】
  - 現在は商品同士の交換のみ
  - 相手が欲しい商品を持っていない場合、取引ができない
  - 購入オプションを追加することで、取引の幅を広げる

【基本方針】
  ✓ UI・チャット画面はそのまま使用
  ✓ 取引の種類（交換 or 購入）を判別できるようにする
  ✓ データベースに購入フロー用の情報を追加


================================================================================
2. 現状の交換フローの整理
================================================================================

【交換フローの流れ】

[1] 申請者（Buyer）が取引を申請
    ├─ 相手（Seller）の商品を選択
    └─ 自分の交換に出す商品を選択

[2] 申請を受けた人（Seller）が対応
    ├─ 申請を承認 or 拒否
    └─ 承認の場合、自分の交換に出す商品を選択

[3] お互いが商品を選択した状態
    └─ status: 'purchased'（取引成立）

[4] 発送
    ├─ Buyer が自分の商品を発送
    └─ Seller が自分の商品を発送

[5] 受け取り確認
    ├─ Buyer が相手の商品受け取りを確認
    └─ Seller が相手の商品受け取りを確認

[6] 両者が確認完了
    └─ status: 'completed'（取引完了）
    └─ アーカイブに保存


【現在のデータベース構造】

trades テーブル:
  - trade_id
  - item_id (Seller の商品)
  - seller_id (申請を受けた人)
  - buyer_id (申請者)
  - seller_exchange_item_id (Seller が選択した交換商品)
  - buyer_exchange_item_id (Buyer が選択した交換商品)
  - status ('pending', 'purchased', 'shipped', 'completed', 'cancelled')
  - is_buyer_confirmed (Buyer の受け取り確認)
  - is_seller_confirmed (Seller の受け取り確認)


================================================================================
3. 新しい購入フローの設計
================================================================================

【購入フローの流れ】

[1] 申請者（Buyer）が取引を申請
    ├─ 相手（Seller）の商品を選択
    └─ 相手の商品選択モーダルを表示

[2] モーダルで商品選択
    ├─ 相手が持っている商品がある → 交換フロー（従来通り）
    └─ 相手が持っている商品がない → モーダルを閉じて「購入」に切り替え

[3] 購入モードに切り替え
    ├─ 申請者（Buyer）が購入金額を提案
    └─ チャットで金額を送信

[4] 金額の合意
    ├─ Seller が金額を確認
    ├─ Seller が「OK」ボタンを押す（金額承認）
    ├─ Buyer が最終確認で「OK」ボタンを押す
    └─ 両者が承認 → 購入成立

[5] 決済
    ├─ Buyer が決済を実行（Stripe経由）
    └─ 決済完了 → status: 'paid'

[6] 発送
    ├─ Seller が商品を発送
    └─ 追跡番号を入力 → status: 'shipped'

[7] 受け取り確認
    ├─ Buyer が商品到着を確認
    └─ 「受け取り完了」ボタンを押す → status: 'buyer_received'

[8] 取引完了
    ├─ Seller が取引を終了
    └─ 「取引完了」ボタンを押す → status: 'completed'
    └─ アーカイブに保存

4. 交換 vs 購入 の違い
================================================================================

┌──────────────┬────────────────────┬────────────────────┐
│ 項目         │ 交換               │ 購入               │
├──────────────┼────────────────────┼────────────────────┤
│ 商品の流れ   │ お互いの商品を交換 │ Seller → Buyer     │
├──────────────┼────────────────────┼────────────────────┤
│ 金銭の発生   │ なし               │ あり               │
├──────────────┼────────────────────┼────────────────────┤
│ 決済         │ 不要               │ 必要（Stripe）     │
├──────────────┼────────────────────┼────────────────────┤
│ 発送         │ 双方向             │ Seller → Buyer     │
│              │ (お互いが発送)     │ (Sellerのみ発送)   │
├──────────────┼────────────────────┼────────────────────┤
│ 受け取り確認 │ 双方向             │ Buyerのみ          │
│              │ (お互いが確認)     │                    │
├──────────────┼────────────────────┼────────────────────┤
│ 完了条件     │ 両者が受け取り確認 │ Buyer受取確認      │
│              │                    │ + Seller取引終了   │
├──────────────┼────────────────────┼────────────────────┤
│ ステータス   │ pending            │ pending            │
│ 遷移         │ → purchased        │ → price_proposed   │
│              │ → shipped          │ → price_agreed     │
│              │ → completed        │ → paid             │
│              │                    │ → shipped          │
│              │                    │ → buyer_received   │
│              │                    │ → completed        │
└──────────────┴────────────────────┴────────────────────┘

5. データベース設計の変更案
================================================================================

【trades テーブルに追加するカラム】

┌──────────────────────┬──────────┬────────────────────────┐
│ カラム名             │ 型       │ 説明                   │
├──────────────────────┼──────────┼────────────────────────┤
│ trade_type           │ ENUM     │ 'exchange' or 'purchase'│
│                      │          │ 取引の種類             │
├──────────────────────┼──────────┼────────────────────────┤
│ purchase_price       │ DECIMAL  │ 購入金額（円）         │
│                      │(10,2)    │ 購入の場合のみ使用     │
├──────────────────────┼──────────┼────────────────────────┤
│ price_proposed_by    │ INT      │ 金額を提案したユーザーID│
│                      │          │ (通常はBuyer)          │
├──────────────────────┼──────────┼────────────────────────┤
│ is_price_agreed_seller│ BOOLEAN │ Sellerが金額に合意したか│
├──────────────────────┼──────────┼────────────────────────┤
│ is_price_agreed_buyer│ BOOLEAN  │ Buyerが金額に合意したか│
├──────────────────────┼──────────┼────────────────────────┤
│ payment_intent_id    │ VARCHAR  │ Stripe PaymentIntent ID│
│                      │(255)     │ 決済情報               │
├──────────────────────┼──────────┼────────────────────────┤
│ paid_at              │ TIMESTAMP│ 決済完了日時           │
├──────────────────────┼──────────┼────────────────────────┤
│ buyer_received_at    │ TIMESTAMP│ Buyer受取確認日時      │
│                      │          │ （購入の場合のみ）     │
└──────────────────────┴──────────┴────────────────────────┘


【既存カラムの使い分け】

交換の場合:
  - seller_exchange_item_id: Sellerの交換商品
  - buyer_exchange_item_id: Buyerの交換商品
  - is_seller_confirmed: Sellerの受け取り確認
  - is_buyer_confirmed: Buyerの受け取り確認

購入の場合:
  - seller_exchange_item_id: NULL
  - buyer_exchange_item_id: NULL
  - is_seller_confirmed: 取引終了の確認（Sellerが最後に押す）
  - is_buyer_confirmed: 商品受取の確認（Buyerが押す）


【status の値の追加】

現在:
  'pending', 'purchased', 'shipped', 'completed', 'cancelled'

追加:
  'price_proposed'   - 金額が提案された
  'price_agreed'     - 金額に両者が合意
  'paid'             - 決済完了
  'buyer_received'   - Buyerが受け取り確認（購入のみ）

8. API設計案
================================================================================

【新規API】

1. POST /api/propose_purchase_price
   ────────────────────────────────────────
   用途: 購入金額を提案
   パラメータ:
     - trade_id: 取引ID
     - price: 提案金額
     - message: メッセージ（任意）
   処理:
     - trade_type を 'purchase' に設定
     - purchase_price を保存
     - status を 'price_proposed' に変更


2. POST /api/agree_purchase_price
   ────────────────────────────────────────
   用途: 金額に合意
   パラメータ:
     - trade_id: 取引ID
     - user_type: 'seller' or 'buyer'
   処理:
     - is_price_agreed_seller or is_price_agreed_buyer を TRUE に設定
     - 両者が合意したら status を 'price_agreed' に変更


3. POST /api/pay_for_purchase
   ────────────────────────────────────────
   用途: 購入代金を決済
   パラメータ:
     - trade_id: 取引ID
     - payment_method_id: Stripeの決済方法ID
   処理:
     - Stripe で決済を実行
     - payment_intent_id を保存
     - paid_at に現在時刻を設定
     - status を 'paid' に変更


4. POST /api/confirm_buyer_received
   ────────────────────────────────────────
   用途: 購入者が商品受け取りを確認
   パラメータ:
     - trade_id: 取引ID
   処理:
     - is_buyer_confirmed を TRUE に設定
     - buyer_received_at に現在時刻を設定
     - status を 'buyer_received' に変更


5. POST /api/complete_purchase_trade
   ────────────────────────────────────────
   用途: 発送者（Seller）が取引を完了
   パラメータ:
     - trade_id: 取引ID
   処理:
     - is_seller_confirmed を TRUE に設定
     - status を 'completed' に変更
     - アーカイブに保存


【既存APIの修正】

1. POST /api/create_trade
   ────────────────────────────────────────
   追加パラメータ:
     - trade_type: 'exchange' or 'purchase' (デフォルト: 'exchange')


2. GET /api/get_trade_detail
   ────────────────────────────────────────
   返却値に追加:
     - trade_type
     - purchase_price
     - is_price_agreed_seller
     - is_price_agreed_buyer
     - payment_intent_id
     - paid_at
     - buyer_received_at
