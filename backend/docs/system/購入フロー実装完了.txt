## 概要

交換機能に加えて、「購入」機能を実装しました。
ユーザーが交換する商品を持っていない場合、金額を提案して購入できるようになります。

## 購入フローの流れ
================================================================================

### ステップ1: 金額提案（Buyer）
状態: pending → price_proposed

1. Buyerがチャット画面で「購入モードで金額を提案」ボタンをクリック
2. 金額提案モーダルが開く
3. 金額とメッセージ（任意）を入力
4. 手数料込みの総額が表示される
5. 提案すると、trade_typeが'purchase'に、statusが'price_proposed'に変更

### ステップ2: 金額合意（Seller & Buyer）
状態: price_proposed → price_agreed

1. 提案された金額が表示される
2. Sellerが「この金額で販売する」をクリック → is_price_agreed_seller = TRUE
3. Buyerが「この金額で購入する」をクリック → is_price_agreed_buyer = TRUE
4. 両者が合意すると、statusが'price_agreed'に変更

### ステップ3: 決済（Buyer）
状態: price_agreed → paid

1. 「決済に進む」ボタンが表示される
2. クリックすると決済モーダルが開く
3. 金額詳細（商品代金 + Stripe手数料 3.6% + プラットフォーム手数料 10%）が表示
4. 決済を実行（現在はテスト実装）
5. statusが'paid'に変更

### ステップ4: 発送（Seller）
状態: paid → shipped

1. Sellerが商品を発送
2. 発送情報（追跡番号、配送会社）を入力
3. statusが'shipped'に変更

### ステップ5: 受取確認（Buyer）
状態: shipped → buyer_received

1. Buyerが商品を受け取る
2. 「商品を受け取りました」チェックボックスをチェック
3. 確認すると支払いが確定（エスクロー解除）
4. statusが'buyer_received'に変更

### ステップ6: 取引完了（Seller）
状態: buyer_received → completed

1. Sellerに「取引を完了する」ボタンが表示される
2. 受取金額（商品代金 - プラットフォーム手数料 10%）が表示
3. 完了すると、statusが'completed'に変更
4. 取引履歴に保存される

## 手数料構造
================================================================================

### Buyerが支払う金額:
- 商品代金: ¥X
- Stripe決済手数料: ¥X × 3.6%
- プラットフォーム手数料: ¥X × 10%
- 合計: ¥X × 1.136

### Sellerが受け取る金額:
- 商品代金: ¥X
- プラットフォーム手数料: -¥X × 10%
- 合計: ¥X × 0.9

### エスクロー方式:
決済金額は商品受取確認までプラットフォームで保管されます。
Buyerが受取確認後、Sellerへの支払いが確定します。

## 主要な設計判断
================================================================================

### 1. trade_typeフィールドの追加理由:
- 既存の交換フローを壊さない
- 購入と交換で異なるロジックを適用
- DEFAULT 'exchange'で後方互換性を維持

### 2. エスクロー方式の採用理由:
- 買い手保護（商品が届かない詐欺を防止）
- Mercari等の主要プラットフォームの標準
- 受取確認後に支払い確定

### 3. 手数料10%の理由:
- Mercariと同じ水準
- 業界標準的な手数料率
- プラットフォーム運営コストをカバー

### 4. 両者合意フローの理由:
- Buyerの提案だけでなくSellerの同意も必要
- 双方が納得した金額で取引
- トラブル防止
