## 修正内容の概要

購入フローの開始者を **Buyer（申請者）から Seller（申請された側）に変更**しました。

### 修正前（誤り）:
Buyer（申請者）が「交換商品がない」と判断して購入モードに切り替え

### 修正後（正しい）:
Seller（申請された側）が「交換する商品がない」と判断して購入を提案

## 正しい購入フローの流れ
================================================================================

### ステップ1: 交換申請
- Buyer（申請者）が Seller（申請された側）の商品に対して交換申請
- status: pending

### ステップ2: Seller が商品を確認
- Seller は2つの選択肢がある:
  1. **交換商品を選択する** → 交換フローに進む
  2. **購入してもらう（金額を提案）** → 購入フローに進む

### ステップ3: 購入金額の提案（Seller）
状態: pending → price_proposed

**誰が**: Seller（申請された側）
**何を**: 「交換する商品がない場合、購入してもらう」ボタンをクリック
**内容**:
  - 希望販売金額を入力
  - メッセージ（任意）を入力
  - 受取金額が表示される（商品代金 - 手数料10%）
  - 提案すると、trade_typeが'purchase'、statusが'price_proposed'に変更

### ステップ4: 金額合意（Seller & Buyer）
状態: price_proposed → price_agreed

**Sellerの画面**:
  - 「提案した金額 ¥X で販売する」ボタンが表示
  - クリックすると is_price_agreed_seller = TRUE

**Buyerの画面**:
  - 「¥X で購入する」ボタンが表示
  - クリックすると is_price_agreed_buyer = TRUE

**両者が合意すると**:
  - statusが'price_agreed'に変更
  - 決済ボタンが表示される

### ステップ5: 決済（Buyer）
状態: price_agreed → paid

1. Buyerの画面に「決済に進む」ボタンが表示
2. 決済モーダルが開く
3. 支払い金額（商品代金 + Stripe手数料 3.6% + プラットフォーム手数料 10%）が表示
4. 決済実行（現在はテスト実装）
5. statusが'paid'に変更

### ステップ6: 発送（Seller）
状態: paid → shipped

1. Sellerが商品を発送
2. 発送情報（追跡番号、配送会社）を入力
3. statusが'shipped'に変更

### ステップ7: 受取確認（Buyer）
状態: shipped → buyer_received

1. Buyerが商品を受け取る
2. 「商品を受け取りました」をチェック
3. エスクローが解除され、Sellerへの支払いが確定
4. statusが'buyer_received'に変更

### ステップ8: 取引完了（Seller）
状態: buyer_received → completed

1. Sellerに「取引を完了する」ボタンが表示
2. 受取金額が表示される
3. 完了すると、statusが'completed'に変更
4. 取引履歴に保存

## ボタン表示問題の修正
================================================================================

### 問題:
「交換商品を選択する」ボタンが表示されなくなった

### 原因:
SelectItems を `trade_type === "exchange"` で囲んだため、
初期状態（trade_type が undefined）で表示されなくなった

### 修正:
条件を `trade_type !== "purchase"` に変更
→ 購入モード以外（undefined, 'exchange'）では表示される

## 表示条件の整理
================================================================================

### Seller（申請された側）の画面

**pending 状態**:
  1. 「交換商品を選択する」ボタン
     条件: status === 'pending' && !hasSellerSelectedItem
     → クリックすると交換フローに進む

  2. 「購入してもらう（金額を提案）」ボタン
     条件: status === 'pending' && !hasSellerSelectedItem && trade_type !== 'purchase'
     → クリックすると購入フローに進む

**price_proposed 状態**:
  - 金額合意UI が表示される
  - 「提案した金額 ¥X で販売する」ボタン

**price_agreed 状態**:
  - 金額合意完了メッセージ
  - 「決済をお待ちください」

**paid 状態**:
  - 「発送する」ボタン

**shipped 状態**:
  - Buyerの受取確認を待つメッセージ

**buyer_received 状態**:
  - 「取引を完了する」ボタン
  - 受取金額の表示

### Buyer（申請者）の画面

**pending 状態**:
  - 申請した商品の情報が表示される
  - Sellerの選択を待つメッセージ

**price_proposed 状態**:
  - 金額合意UI が表示される
  - 「¥X で購入する」ボタン

**price_agreed 状態**:
  - 「決済に進む」ボタン

**paid 状態**:
  - 「発送をお待ちください」メッセージ

**shipped 状態**:
  - 「商品を受け取りました」チェックボックス

**buyer_received 状態**:
  - 「Sellerが取引を完了するまでお待ちください」メッセージ

## 金額の流れ
================================================================================

### Seller が提案する金額:
例: ¥3,000

### Seller が受け取る金額:
¥3,000 - (¥3,000 × 10%) = ¥2,700

### Buyer が支払う金額:
¥3,000（商品代金）
+ ¥108（Stripe手数料 3.6%）
+ ¥300（プラットフォーム手数料 10%）
= ¥3,408

### プラットフォームの収益:
¥300（商品代金の10%）

## 重要ポイント
================================================================================

1. **購入フローの開始者は Seller**
   - Seller が「交換商品がない」と判断
   - Seller が希望販売価格を提案

2. **Seller は2つの選択肢を持つ**
   - 交換商品を選択 → 交換フロー
   - 購入してもらう → 購入フロー

3. **金額提案は Seller の権利**
   - Seller が適切な価格を設定
   - Buyer は合意するか拒否するか選択

4. **エスクロー方式**
   - Buyer の決済は即時実行
   - Seller への支払いは受取確認後
   - 買い手保護を実現

5. **手数料の透明性**
   - Seller: 受取金額を明確に表示
   - Buyer: 総支払額を明確に表示
